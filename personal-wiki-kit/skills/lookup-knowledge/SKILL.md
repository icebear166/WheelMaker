# 查询个人 Wiki

先查询可能复用的长期知识，再开展实质工作。默认只读 Git `HEAD`；不要把未提交内容描述成正式知识。

## 定位配置

1. 读取 `~/.personal-wiki/config.json`，只使用其中的 `repositoryPath` 定位私人 Wiki；`publicUrl` 只用于给出受保护网页链接。
2. 读取 `~/.personal-wiki/project-routing.json`，根据当前工作区或具体来源文件解析项目 ID。
3. 不读取 WheelMaker 或其他工程的 `config.json` 来推断归属，不把 `remote`、`defaultBranch`、项目映射或凭据写入用户配置。
4. Skill 可以随 Kit 更新而整体替换；上述两个用户配置文件位于 Skill 目录之外，更新 Skill 时不得修改或删除。

## 解析项目

调用用户级 Personal Wiki 命令：

```text
personal-wiki route --workspace <当前工作区>
personal-wiki route --source <来源绝对路径> [--source <来源绝对路径> ...]
```

遵守以下结果语义：

- 每个来源只采用最长的包含根路径；
- 多个来源的项目 ID 合并并去重；
- 多个本机工程可以映射到同一个 Wiki 项目；
- 未匹配时保持项目 ID 为空，不猜测目录名，不写入保留值 `unassigned`；网站会把空项目数组显示为“未指定项目”。

## 查询已提交知识

从任务目标提取少量稳定关键词，优先使用模块名、技术名、错误现象和决策主题：

```text
personal-wiki query --query <关键词> --project <项目ID> --limit 5
```

- `--project` 可以重复；没有已解析项目时省略。
- 默认结果必须标记为 `committed-head` 和“已提交快照（HEAD）”。
- 先根据标题、摘要、知识分类、项目和分数筛选，再读取命令返回的有限正文。
- 首轮不足时最多再换一组更宽或更准确的关键词，不做无界扫描。
- 项目提示只影响相关性；项目内没有匹配时允许回退到跨项目结果。

只有用户明确要求查看本地未提交知识或发布前预览时，才增加 `--working-tree`。此时必须把结果标记为 `unpublished-working-tree` 和“未发布工作区”，并明确说明尚未提交。

## 使用结果

- 把高相关条目作为背景和可复用约束，不把它们当成替代当前代码验证的绝对真理。
- 结论可能过期或与当前实现冲突时，检查当前工程并指出差异。
- 只概括真正影响本次工作的内容；必要时给出文章 ID 或配置中的受保护网站地址。
- 整个查询流程保持只读，不修改 Wiki、Git、用户配置、工程路由或远端。
- 查询失败时简要说明原因并继续使用当前上下文，不阻塞原任务。
- 任务产生新的可靠长期知识时，交给 `$publish-knowledge` 提出候选；查询本身不构成发布批准。
