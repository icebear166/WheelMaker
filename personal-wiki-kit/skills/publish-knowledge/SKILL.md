# 发布可靠知识

维护以私人 Git 仓库中的 Markdown 文章和 YAML 注册表为唯一事实来源的个人 Wiki。主动识别长期结论，但始终把“提出候选”和“正式发布”分开。

## 执行批准门槛

- 尚未获得批准时，只提出候选；不要编辑 Wiki、暂存文件、提交或推送。
- 每个候选列出准确标题、文章 ID、知识类型、分类、项目、置信度、依据和计划改动文件。
- 只有用户在当前对话中明确批准已展示的具体候选后，才能写入。
- “批准发布以上全部候选”“批准第 1、3 条”等直接指向当前候选清单的表达属于有效批准。
- 沉默、普通继续请求、其他代码改动的批准或旧对话中的批准都不属于 Wiki 发布批准。
- 候选内容、分类、项目或文件范围发生实质变化时，展示新差异并重新请求批准。
- 批准只覆盖列明的知识文件及必要注册表项；不授权保存凭据、夹带无关改动、创建仓库、改变可见性、改写历史或强制推送。

## 定位私人 Wiki 与项目

1. 读取 `~/.personal-wiki/config.json`，从 `repositoryPath` 定位私人仓库。
2. 读取 `~/.personal-wiki/project-routing.json`，通过用户级命令解析来源：

```text
personal-wiki route --source <来源绝对路径> [--source <来源绝对路径> ...]
```

3. 多个工程根可以映射到同一个项目；每个来源采用最长包含根，多个来源合并项目 ID。
4. 未匹配来源使用 `projects: []`，不写入 `unassigned`，不根据仓库名或目录名猜测项目。
5. 路由出现未知项目 ID 时停止普通发布；把新增项目定义和首批受影响文章一同列为候选请求批准。
6. 不从配置读取或写入 `remote`、`defaultBranch`；发布目标由私人 Git 仓库本身推断。
7. Skill 可以随 Kit 更新而整体替换；用户配置和 `project-routing.json` 位于 Skill 目录之外，更新时必须保留。

初始化器会安装 `%USERPROFILE%/.personal-wiki/bin/personal-wiki.cmd`。下文的 `personal-wiki` 表示调用这个用户级入口；不要假设它已经加入系统 `PATH`，也不要修改入口中锁定的 Kit 位置。

## 选择可靠候选

只提出同时满足以下条件的内容：

- 有长期复用价值，脱离当前对话仍能独立理解；
- 由当前仓库、正式文档、已确认决策或验证结果支持；
- 能说明适用范围、边界和置信度；
- 不与现有条目重复；同一主题优先更新原文章。

排除猜测、未解决问题、临时变通、任务状态、原始对话、草稿、收件箱材料、整份文档复制和任何凭据。

创建或修改内容前读取[文章合同](references/article-contract.md)。知识类型和分类描述“以后会怎样查找”，项目只描述适用范围，不是存储目录。

## 提出候选

每个候选至少包含：

1. 稳定标题和 kebab-case 文章 ID；
2. 注册表中的知识类型与分类；
3. 项目 ID 和显示名，或“未指定项目”；
4. 一句话可靠结论；
5. 置信度与依据；
6. 新建或更新；
7. 准确文件范围：`content/articles/{id}.md`、`content/registry/articles.yaml`，以及单独获批的分类、项目或附件变更。

导入文档时每批处理 5 至 15 项，先识别重复与敏感材料，再提出清理后的候选。

## 发布已批准候选

获得准确批准后：

1. 检查私人仓库的说明、Git 状态、三份注册表、相关文章和文章合同；保留无关用户改动，目标文件已有重叠改动时停止。
2. 新文章写入 `content/articles/{id}.md`；分类、项目、顺序只写入 `content/registry/articles.yaml` 对应注册项。
3. 改变文章归属时只修改注册项，不移动 Markdown。修改总目录、二级目录或项目定义前必须确认它们已单独列入获批候选。
4. 运行 `personal-wiki check`，修复全部内容、链接、附件、秘密和注册表错误。
5. 审查差异，确认没有原始材料、凭据或未批准文件。
6. 调用 `personal-wiki publish` 完成知识白名单暂存、提交和可选普通推送；不要使用 `git add -A`、强制推送或历史改写。
7. 没有远端时如实报告“已本地提交，未部署”；有远端但无法观察部署时报告“已推送，部署状态未知”。只有取得健康检查或工作流成功证据时才报告在线发布成功并给出 `publicUrl`。

## 处理失败

- 校验失败时保持未提交，报告具体文章、注册项和规则。
- 检测到秘密时从候选、暂存和生成物中移除，不在回复中复述秘密值。
- 合并或变基发生语义冲突时保留可恢复状态并请求用户决定。
- 网络、认证或部署失败时不降低 Git、SSH、TLS 或主机身份校验。
- 推送成功但部署失败时保留提交，并说明线上仍使用上一份原子发布版本。

## 报告结果

说明创建或更新的文章、注册项、提交标识、校验结果、推送状态和部署状态。只有确认部署成功后，才提供配置中的受保护 Wiki 地址。
