1. Make main.tsx a bootstrap module

Strongin-process
app/web/src/main.tsxapp/web/src/shell/ResponsiveShell.tsxapp/web/src/chat/*app/web/src/file/*app/web/src/git/*app/web/src/settings/*
Before
flowchart LR
  M[main.tsx\nbootstrap + shell + chat + file + git + settings + code] --> C[chat modules]
  M --> F[file modules]
  M --> G[git modules]
  M --> S[settings modules]
  M --> R[Registry / Workspace modules]
  T[60 text-scan tests] -.red.-> M
  classDef leak stroke:#dc2626,stroke-width:2px;
  class T leak;
After
flowchart LR
  B[main.tsx\nbootstrap] --> A[WorkspaceApp module]
  A --> SH[Responsive Shell module]
  SH --> CS[Chat surface module]
  SH --> FS[File surface module]
  SH --> GS[Git surface module]
  SH --> SS[Settings surface module]
  A --> W[Workspace data module]
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a;
  class A deep;
Problem
`main.tsx` is shallow: its interface is nearly the whole implementation, so every surface change requires reading one huge module.
Solution
Move render blocks and local helpers by Workspace concept, leaving `main.tsx` as createRoot, global CSS, and `WorkspaceApp` bootstrap.
Benefits
locality: surface bugs concentrate
leverage: entry imports one module
tests hit surface modules
deletion test exposes real owners
ADR note: aligns with the 2026-05-14 Responsive Shell decision; continue passing shared content into DesktopShell and MobileShell.
