# Workspace UI 定向演进

## 目标

WheelMaker Workspace 当前已经形成面向开发者的高密度工作区界面，并具备桌面、竖屏移动端、深浅主题、会话管理、聊天输入、设置与多种状态反馈能力。本次迭代在保留现有功能、信息架构、宽窄两档响应式和主要交互的前提下，统一视觉基础，改善核心工作流的层级、质感、状态完整性与动效表现。设计以竖屏移动端为优先约束，同时保证桌面宽屏体验；整体采用定向演进，不进行视觉推倒重来。

## 决策

- 采用定向演进：保留当前开发工具气质、React/原生 CSS 技术栈、功能、信息架构和主要交互，只做针对性视觉升级。
- 核心覆盖范围为应用壳层、会话侧栏、Chat 消息区、聊天输入区样式、Settings、连接状态及公共加载/空数据/错误反馈。
- File 和 Git 页面不纳入本次页面级视觉改造，也不删除其底层组件、状态或服务能力；它们可以被动继承公共 Token，但不进行专属样式重构。
- Port Relay、日志、Token Stats、Skills 等详情页不单独重构，只继承本次建立的公共视觉规范。
- 保留现有冷灰中性色与蓝色强调色，允许微调深浅主题的背景、面板、边框、文字及强调色数值。
- 保留 IBM Plex Sans、JetBrains Mono 和现有可配置聊天字体；只调整字号层级、字重、行高、字距及数据数字的等宽表现。
- 会话侧栏保持现有内容顺序、搜索位置、分组结构和操作入口；不新增全局新建会话入口，不搬移已有按项目新建会话能力。改动仅限视觉分组、文字层级、间距、选中态、Hub 标签与操作按钮样式。
- Chat 保持现有消息结构和行为。用户消息、Assistant 正文、Thought、单行 Tool call 与回合结束信息的位置不变；`agent_plan` 继续不在正文中显示，Tool call 继续保持单行。
- 聊天输入区保持现有两层结构、图标尺寸和按钮尺寸。仅优化背景、边框、圆角、阴影、颜色与状态层级；整体采用克制、轻量方向，减弱默认阴影和渐变，强调色主要用于聚焦、发送、录音、错误等语义状态。
- Settings 保持现有设置项、分组、顺序、详情入口和移动端快捷栏，只统一页面标题、列表行、控件、说明文字、危险操作和状态样式。
- 保留当前宽屏/窄屏两档及现有布局切换逻辑，不新增第三档响应式模式。
- 竖屏移动端优先验证；保留抽屉、可拖动浮动控件、快捷切换、底部面板、系统返回键、震动反馈和软键盘避让逻辑，只优化视觉表现和窄屏适配。
- 动效采用适度增强：允许增加消息进入、菜单展开和页面切换动效，所有新增动效必须服务于层级、反馈或状态转换，并支持 `prefers-reduced-motion`。
- 允许补齐缺失的骨架、空状态指引、错误反馈和内联重试，但不改变数据协议、请求流程、缓存逻辑或业务状态机。
- 保持 Codicon 为主要图标体系和现有图标尺寸；允许替换少量含义不清或观感不合适的具体图标，不引入全量新图标体系。

## 架构

本次改造分为四个视觉层级：

1. **公共视觉基础**：在现有 CSS 变量基础上建立语义颜色、表面层级、边框、圆角、阴影、焦点和动效 Token，统一深浅主题及公共控件状态。
2. **核心工作区表面**：应用壳层与 ResponsiveShell 继续负责宽窄两档布局；会话侧栏、Chat 和 Settings 保留现有组件边界与行为，只消费统一视觉基础并进行局部样式调整。
3. **公共状态组件**：连接、加载、空数据、错误、重试、禁用和处理中状态采用一致的视觉语言；现有状态逻辑继续作为唯一数据来源。
4. **继承表面**：Port Relay、日志、Token Stats、Skills 等非核心详情页只继承公共 Token 和基础控件样式，不进行信息架构或页面级重排。File/Git 不消费本次页面级改造。

## 验收标准

- 深色和浅色主题均使用统一语义 Token；核心工作区不再依赖相互冲突的中性色、阴影和状态颜色。
- 应用壳层、会话侧栏、Chat、Settings 与公共浮层具有一致的圆角、边框、表面层级和交互状态。
- 会话侧栏的内容顺序、搜索位置、现有操作入口和按项目新建会话流程保持不变。
- 侧栏在不改变信息架构的前提下，项目、会话、Hub 元数据、当前选中项和行内操作具有清晰且一致的视觉层级。
- Chat 的消息顺序、消息类型和交互保持不变；`agent_plan` 不进入正文，Tool call 始终保持单行且不会撑宽窄屏页面。
- Assistant 正文继续采用文档式阅读布局；用户消息、Thought、回合结束信息及操作区只做样式与排版调整。
- 聊天输入区的 DOM 结构、两层布局、图标尺寸及发送/语音按钮尺寸保持不变。
- 输入区默认阴影与渐变得到收敛；聚焦、发送、录音、停止、上传失败等状态能清楚区分，深浅主题下均可辨识。
- `/`、`@`、附件、语音、模型、推理强度和上下文等现有入口在竖屏移动端保持可用，不因视觉调整发生遮挡、溢出或误触区域重叠。
- Settings 的设置项、分组、顺序、详情入口和移动端快捷栏保持不变；标题、列表、控件、说明、危险操作与状态反馈使用统一样式。
- 保持现有宽屏/窄屏两档行为；360px、390px、430px 竖屏宽度下不出现页面级横向滚动、菜单越界、输入区遮挡或软键盘覆盖关键操作。
- 抽屉、浮动控件、快捷切换、底部面板、系统返回键、震动反馈和软键盘避让行为不发生回归。
- 新增消息进入、菜单展开和页面切换动效节奏一致；启用减弱动效后不播放非必要动画。
- 对缺失的加载、空数据和错误场景提供与最终布局匹配的骨架、清晰指引或内联重试；底层数据流程保持不变。
- 所有核心交互按适用场景具备可辨识的默认、hover、pressed、focus-visible、disabled、loading 或 open 状态；不能仅依赖颜色表达关键状态。
- 图标尺寸保持不变；仅在含义或观感明确不足时替换个别图标，整体仍保持 Codicon 视觉一致性。
- Port Relay、日志、Token Stats、Skills 等详情页能够继承公共 Token 与控件状态，但页面结构和功能不发生变化。
- File/Git 页面允许被动继承公共 Token，但页面专属样式、结构、交互及底层功能不因本次改造发生变化。

## 范围之外

- 不新增、删除或重排产品功能与导航入口。
- 不改变会话创建、搜索、归档、恢复、快捷切换或选择流程。
- 不改变 Chat 消息协议、正文内容生成、计划处理或 Tool call 数据结构。
- 不改变聊天输入区结构、图标尺寸、按钮尺寸、语音交互或发送行为。
- 不重组 Settings 信息架构，不合并或删除设置项。
- 不新增第三档响应式模式，不重构现有移动端导航行为。
- 不改变 Registry 协议、数据请求、缓存、存储、通知或错误恢复状态机。
- 不引入新的 UI 框架、动画框架或全量图标库。
- 不对 File/Git 页面进行页面级针对性视觉或结构改造；仅允许被动继承公共 Token。
- 不对 Port Relay、日志、Token Stats、Skills 等详情页做页面级重设计。
