# 顶栏与菜单统一

## 目标

重整 Chat 顶栏中 PC 端的应用入口、Project 与 Hubs 布局，以及其关联的下拉菜单视觉，使其在保留既有 PC/移动端信息架构与 Hubs 管理能力的前提下，成为层级清晰、材质统一的深色工具界面。

## 决策

- 移动端继续只面向聊天场景：Workspace 保留在顶部，整段 Prompt 标题可点击；不向 PC 端对齐该布局。
- PC 端左侧顶栏按「WheelMaker 标记（应用菜单）→ Project → Hubs」排列。WheelMaker 标记和 Hubs 不压缩，Project 获得二者之间的全部剩余空间。
- Project 是主信息：名称使用主文字色与明确字重；下拉箭头维持次级色。Project 只在物理空间不足时省略，不再采用固定 116px 的硬裁剪。
- 取消悬浮式齿轮设置入口。以非徽标化、紧凑的 WheelMaker 标记作为应用入口，统一承接 Settings、Dev Mode 与 Desktop update；菜单首项为 Settings，其余仅呈现既有桌面端应用级操作及其现有条件，不新增功能。
- Project、Prompt 历史、Hubs 与应用菜单采用同一套瞬态菜单外壳：深色半实底（`surface-overlay 88%`）、弱 `blur(12px)`、8px 圆角、4px 内边距、细边框与浅阴影，以及统一的进入与退出动画；在减少透明度偏好下回退为实心表面。
- Hubs 保留完整管理面板，不迁入 Settings，也不缩减既有项目与配色管理能力。其外壳必须使用共享菜单材质，而非独立的检查器面板样式。
- Hubs 的分组行使用小色点、名称与展开指示表达层级；展开后的项目列表缩进展示。移除整条左侧色带等检查器式装饰；颜色编辑仍由小面积的配色控制触发。

## 架构

顶栏保留平台专属的渲染分支：移动端沿用 Workspace 与可点击 Prompt，PC 端由固定左段、中部 Prompt 标题和右侧工作区操作构成。PC 左段的应用入口、Project 与 Hubs 共享一个弹性布局容器；Project 是唯一可增长且可缩略的成员。

所有顶栏瞬态菜单继续沿用现有菜单挂载、外点关闭、Esc 与进退场控制路径，但改为读取同一组菜单表面与动效样式。Hubs 在共享外壳内保留自己的层级内容和配色子操作。

## 流程

1. 用户在 PC 顶栏点击 WheelMaker 标记，打开包含 Settings 与现有桌面应用级操作的应用菜单。
2. 用户点击 Project 或 Hubs，分别打开项目切换菜单或完整 Hubs 管理面板；任一菜单关闭后均按统一退场流程卸载。
3. 用户在 Hubs 中展开 Hub 查看缩进项目，或打开既有颜色控制完成配色管理；这些操作不改变 Hub 管理能力与数据行为。

## 验收标准

- 移动端顶部仍显示 Workspace，且整段 Prompt 标题仍可点击；PC 中部标题的 Windows 拖拽留白策略不变。
- PC 左侧顶栏中，WheelMaker 标记与 Hubs 不被压缩；Project 持续填满其间余量，并在可用宽度内完整显示，空间确实不足时才以省略号截断。
- Project 名称的可读性强于箭头和辅助控件，不呈现为褪色的次要文字。
- 不再出现孤立的悬浮齿轮；WheelMaker 标记能打开应用菜单，Settings 为首项，且菜单不新增当前不存在的操作。
- 所有列出的顶栏菜单使用一致的表面、圆角、内边距、边框、阴影、进场与退场规则；减少透明度与减少动效偏好均有可用降级。
- Hubs 可继续展开项目、管理既有配色与执行原有操作；视觉上不再通过整条彩色侧轨或独立面板材质表达。
- 窄窗口和不同 PC 侧栏模式下，顶栏控件不重叠、不越界，Hubs 不被压缩。

### 测试

- 为 PC 顶栏布局与菜单触发补充或调整现有组件测试，覆盖应用菜单内容、Project 的弹性截断规则与 Hubs 的主要展开/颜色控制路径。
- 在桌面宽度、窄桌面宽度与移动断点进行手动视觉验证，检查菜单材质、层级、进退场和 `prefers-reduced-motion` / `prefers-reduced-transparency` 降级。
- 不改变 Hubs 数据模型、项目切换逻辑、移动端标题交互或 Windows 窗口拖拽实现，因此不为这些行为新增独立功能测试。

## 范围之外

- 不重做聊天正文、右侧工作区、会话侧栏或移动端信息架构。
- 不新增应用级菜单功能，不改变 Settings、更新或开发模式等既有操作的权限与可用条件。
- 不更换品牌标识，不引入新的图标库，也不修改 Hubs 的数据模型或持久化格式。
