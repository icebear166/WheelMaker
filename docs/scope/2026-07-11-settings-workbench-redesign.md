# 设置工作台设计重构

## 目标

重塑设置首页及 Update、Skills、Port Relay、Token Stats、Connection Status、Database、Logs 等所有现有详情页的视觉层级，使其从同质的“分组表单”转为具有清晰阅读轨道、恰当深度和一致交互反馈的设置工作台。保留全部既有内容、信息架构、路由、设置项、字段、事件和状态逻辑。

## 决策

- 采用“有质感的克制工作台”方向：以冷静的中性色、清晰排版、细边界、柔和分层阴影建立深度；不使用厚重玻璃、显著蓝色填充、营销页式图像或装饰性渐变。
- 保持现有字体、主题色和深浅主题机制，不在设置页引入独立字体或第二套品牌色。
- 桌面设置弹层扩展为约 920px 的自适应画布。首页在宽度足够时使用双轨分区，按现有 DOM 顺序流式排列；窄桌面与移动端退回单列。
- 详情页保持单条阅读轨道。Skills 的现有详情侧栏继续保留，并与主面板使用同一深度、边界和标题体系。
- 移动端保持单列、现有 56px 设置行触控高度、底部五项快捷栏和安全区处理；不以压缩触控区域换取密度。
- 首页分区、详情顶部导航、数据摘要、表单控件、操作按钮、危险操作、空状态、加载状态和错误状态共享统一视觉令牌。页面可保留各自的信息结构，不新增或删除内容。
- 动画仅用于页面切换和控件反馈，使用 opacity 与 transform 的短时过渡；尊重 `prefers-reduced-motion`，不以位置或尺寸动画制造效果。
- 危险操作保持独立且可辨识的危险色反馈，不与普通导航行混淆。

## 架构

设置视觉体系围绕现有 `SettingsSurface`、`SettingsRootContent` 和 `settings.css` 演进，不迁移框架或引入组件库。样式收敛为四层：设置工作台容器、首页分区与行项目、通用详情壳与内容轨道、页面专用的数据与管理块。现有详情组件继续输出当前内容和事件，仅使用统一的共享样式契约获得一致外观。

## 验收标准

- 设置首页在桌面宽画布下呈现清晰的双轨分区；分区内容与 DOM 顺序、名称和设置项完全不变。
- 主页分区具备可辨识的层级，但不再依赖满屏大写标题、等高卡片和重复的重边框。
- 所有详情页具有一致的顶部导航、内容宽度、留白、数据块和操作反馈；Skills 侧栏在宽屏与窄屏均可用。
- Update、Skills、Port Relay、Token Stats、Connection Status、Database、Logs 的加载、空、错误、数据和危险操作状态保持功能正确，并获得统一但不抹平语义差异的视觉处理。
- 移动端始终为单列；设置行维持至少 56px 高度，底部快捷栏可见、可点按并适配安全区。
- 深浅主题下文字、边界、表单控件、焦点环和危险状态均保持可读；焦点反馈位于控件或其可见外框，不出现局部高亮块。
- 鼠标悬停、触摸按下和键盘焦点都有克制的反馈；减少动态偏好下关闭非必要动画。
- 不改变设置标题、表单字段、默认值、导航入口、路由、数据请求、持久化、事件处理或可访问性语义。

### 测试

- 更新设置 UI 源码结构测试，覆盖首页双轨断点、移动单列、共享详情壳、快捷栏与关键状态样式。
- 重跑现有设置功能测试，确保所有现有设置项、详情导航和 Skills 侧栏结构不回归。
- 运行 Web TypeScript 检查、完整测试套件和生产构建。
- 手动检查深浅主题下的桌面宽画布、窄桌面与竖屏移动端设置页。

## 范围之外

- 不修改设置内容、分组名称、路由、快捷栏条目、表单字段、数据模型、网络请求或设置持久化逻辑。
- 不改造文件、Git 或其他非设置页面。
- 不引入第三方设计系统、字体或图像资产。
