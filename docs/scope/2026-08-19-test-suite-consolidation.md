# 双端测试套件收敛

## 目标

在不改变 WheelMaker 生产行为、协议版本或测试运行入口的前提下，收敛 Go 服务端和 Workspace Web UI 的测试套件：每个 Go 测试包只保留一个测试文件，删除重复、脆弱或没有独立回归价值的测试，并保留能够证明核心行为、安全边界和数据契约的最小测试集。

## 决策基线

### 需求边界

- Go 每个包含测试的包目录最终恰好有一个 `*_test.go` 文件；当前 24 个测试包目录的测试文件需要合并到各自的单一文件中。
- 前端采用激进收敛：删除主要依赖 `readFileSync`、源码字符串、正则或 CSS 文本结构的 UI/wiring 测试；删除与运行时行为测试重复的静态契约测试。
- 保留真实调用模块函数、真实渲染组件或真实跨层请求的测试；保留协议、安全、持久化、构建/发布边界，即使某些边界暂时需要轻量静态契约验证。
- Go 保留协议、安全、持久化、并发、核心生命周期和端到端边界；同一实现路径的重复正向/负向变体合并为表驱动子测试或删除低信息量变体。
- 测试重构不得修改生产代码行为、公开接口、协议版本、部署流程或测试命令入口。
- 不为追求数量删除某个行为边界的唯一回归证据；删除必须基于重复覆盖、只验证实现形状或没有独立可观察结果。

### 技术决策

- Go 以每个测试包目录中的一个规范测试文件承载该包的测试；合并 import、helper、fixture 和测试主体，消除同包重复 setup。
- Go 中语义相同的输入矩阵使用 table-driven subtests；跨不同职责或不同资源生命周期的测试保持独立，避免把失败定位全部隐藏在一个大测试中。
- 前端优先保留 colocated 的模块/组件测试；`app/__tests__` 中与其重复的源码结构测试删除或压缩为一个真实行为测试。只有在没有可行运行时 seam 且边界属于安全、协议、持久化或构建约束时，才保留最小静态检查。
- 不通过关闭 Jest discovery、跳过测试、扩大 mock 或修改生产代码来制造“全绿”；删除的测试必须从测试清单中消失，保留的测试必须实际执行。
- 先建立测试文件/用例/行数基线，实施后以相同统计口径复测，并执行 Go、Jest 和 Web TypeScript 检查。

## 设计视图

### 功能设计

测试套件按风险而不是按历史提交或源码文件数量组织。服务端测试集中表达协议路由、认证授权、数据持久化、资源清理、并发/队列生命周期和关键 provider 行为；前端测试集中表达状态模型、服务请求、关键组件交互和跨端边界。仅证明某个 import、className、CSS selector、调用顺序或源码片段存在的测试不作为独立回归资产，除非它保护无法通过运行时测试表达的安全/协议/构建契约。

### 技术设计

#### 整体方案

实施分为两条相互独立但共享验收口径的整理线：

1. **Go 测试线**：按包读取现有测试文件，保留行为覆盖，合并同包声明和依赖，统一 helper，压缩重复场景，最终每个包只留下一个测试文件。
2. **前端测试线**：按测试信号分类；删除静态 UI/CSS/wiring 套件，保留模块行为、组件交互及安全/协议/持久化/构建边界；对重复域保留行为更强的一份。

两条线均只修改测试文件及必要的测试辅助代码，不触碰 `server` 和 `app/web` 的生产实现。删除或合并后，完整测试命令仍覆盖剩余文件，统计脚本以仓库排除 `dist` 和 `node_modules` 的口径运行。

#### 关键结构

- Go 的合并单位是测试包目录，而不是任意文件名；当前所有有多个测试文件的目录均使用同一个内部 package 名，因此可以在保留 package 声明的情况下合并。
- 前端的保留单位是可观察行为：纯函数输入输出、服务请求/响应、组件渲染和用户事件优先级高于源码文本断言；源代码契约只保留安全、协议、持久化和构建发布所需的最小断言。
- 测试辅助代码必须由保留测试实际使用；合并后删除孤立 helper、重复 fixture 和不再被 discovery 使用的测试文件。

#### 实现流程

先记录 Go 测试包/文件/函数/行数和前端测试文件/suite/test/行数。随后先处理前端高体量且以源码断言为主的套件，再处理各 Go 包的合并与重复场景收敛；每个独立工作单元运行对应的聚焦测试，最后运行双端全量验证。若某个删除候选是唯一的安全、协议或数据持久化证据，则恢复为最小行为测试或保留最小静态检查，而不是直接删除。

### 预估改动面

- `server/cmd/**`、`server/internal/**`：合并当前 24 个测试包目录中的测试文件；重点整理 `hub/client`、`hub/agent`、`registry`、`hub`、`cmd/wheelmaker-desktop` 等高密度测试，删除重复和低信息量场景。
- `app/__tests__/**`、`app/web/src/**/*.test.*`：删除源码/CSS 结构型 UI 测试，合并重复 domain coverage，保留运行时模块和关键安全/协议/持久化/构建边界。
- 不更新 `docs/wiki`；不修改生产实现、协议文档或测试命令配置。

## 验收

- 每个有 Go 测试的包目录恰好存在一个 `*_test.go`，且 `go test ./...` 通过；验证：`Get-ChildItem server -Recurse -Filter '*_test.go'` 按目录计数，以及 `go test ./...`。
- Go 测试文件数从基线 97 降至 24；测试代码行数和测试函数数均低于基线 65,323 行、1,684 个函数；验证：使用实施前相同统计脚本复测。
- 前端测试文件数和测试代码行数至少减少 25%；基线为 308 个文件、50,851 行；验证：排除 `dist`/`node_modules` 后使用相同统计口径复测。
- 前端不再保留以源码/CSS 文本断言为主要信号的大型 UI/wiring 套件；保留的安全、协议、持久化和构建边界测试仍实际执行；验证：测试清单审查和 `npm test -- --runInBand --coverage=false`。
- Jest 全量通过且不再出现基线中的失败套件；验证：`npm test -- --runInBand --coverage=false`，无失败 suite/test。
- Web 类型检查通过；验证：`npm run tsc:web`。
- 生产代码、协议版本、测试命令入口和 wiki 无非目标修改；验证：`git diff --stat`、`git diff -- server app/web` 和最终工作树审查。
